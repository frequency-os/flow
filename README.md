# Frequency

Особиста «операційна система життя»: папки, дошки, фінанси, цілі, планер,
щоденник, читалка, AI-компаньйон, агенція.

---

## Головне правило

**Програму НЕ редагують у `dist/index.html`.**
Редагують файли в `src/` → потім запускають збірку → з'являється `dist/index.html`.

```
src/  (те, що ти правиш)  ──збірка──▶  dist/index.html  (те, що працює)
```

`dist/index.html` — це один великий файл, точно такий самий, як був раніше.
Саме його відкриває браузер, Telegram, iPhone і Android. Ніщо в поведінці
програми не змінилось — змінилось лише те, як код зберігається на диску.

---

## Як зібрати

Подвійний клік по **`build.command`** — і все.

Або в терміналі:

```bash
cd ~/frequency && python3 tools/build.py
```

## Як перевірити, що нічого не зламано

```bash
cd ~/frequency && ./tools/check.sh
```

Скрипт: (1) перевіряє синтаксис усіх JS-файлів справжнім движком JavaScript,
(2) збирає програму, (3) порівнює з еталоном `original/index11.html`.

## Що де лежить

| Тека | Що це |
|---|---|
| `src/index.html` | Каркас: вся HTML-розмітка + маркери `@@INC:...@@`, куди підставляються частини |
| `src/styles/` | Оформлення (CSS) |
| `src/styles/core/` | Основне оформлення, порізане на 15 тем |
| `src/scripts/` | Код (JS) |
| `src/scripts/core/` | Головний код, порізаний на 29 систем |
| `src/scripts/page-editor/` | Редактор сторінки (Notion-стиль) — 9 частин |
| `dist/index.html` | **Готова програма.** Створюється збіркою |
| `original/index11.html` | Недоторканий еталон «як було до розбору» |
| `tools/` | Скрипти збірки та перевірки |
| `CODEMAP.md` | Карта коду (де яка система живе) |

### Маркери в каркасі

У `src/index.html` замість коду стоять маркери:

* `@@INC:styles/04-diary.css@@` — підставити один файл
* `@@INCDIR:scripts/core@@` — підставити **всі** файли з теки, за абеткою

Тому в `core/` файли пронумеровані (`01-…`, `02-…`): **номер = порядок виконання**.
Порядок міняти не можна — код розрахований на нього.

## Автономність (зроблено)

Застосунок більше **не потребує інтернету, щоб відкритися**. Все, що раніше
тягнулося з чужих серверів, тепер лежить усередині:

| Що | Було | Стало |
|---|---|---|
| Шрифти Manrope / Lora / Caveat | Google Fonts | вшиті в `src/styles/00-fonts.css` |
| Telegram Web App SDK | `telegram.org` | локальна копія `src/scripts/00-telegram-sdk.js` |
| JSZip (EPUB) · pdf.js (PDF) · Supabase (вхід) | CDN | `src/vendor/` → `dist/vendor/`, CDN лишився запасним |

Інтернет потрібен лише для того, що без нього не має сенсу: курси валют,
вхід через Google, вбудовані YouTube-відео, AI.

### Оновити вбудоване

```bash
./tools/update-telegram-sdk.sh   # Telegram SDK
python3 tools/build-fonts.py     # шрифти
./tools/build-vendor.sh          # JSZip / pdf.js / Supabase
python3 tools/build.py           # і завжди зібрати після
```

Версії бібліотек **зафіксовані навмисно**. «Остання версія» колись зміниться
сама і зламає те, що вчора працювало — тому оновлення тут завжди твоє рішення.

### Що складається в `dist/`

```
dist/index.html     сама програма
dist/vendor/        3 бібліотеки (потрібні лише для PDF/EPUB/входу)
```
Викладати треба **обидва**. Якщо викласти лише `index.html` — програма
працюватиме, але PDF, EPUB і вхід через Google візьмуться з CDN, тобто
вимагатимуть інтернету.

## Mac-застосунок

```bash
npm start          # запустити застосунок (збере і відкриє)
npm run build:mac  # зробити Frequency.app + .dmg у release/
```

Обгортка — Electron. Вона **не містить логіки застосунку**: усе в `desktop/main.js`
це «рама навколо картини» — вікно, іконка, памʼять про розмір. Сама програма
лишається тим самим `dist/index.html`.

| Файл | Що робить |
|---|---|
| `desktop/main.js` | вікно, схема `app://`, зовнішні посилання, повернення з входу |
| `desktop/preload.js` | місток: дає сторінці `window.flowDesktop` і більше нічого |
| `desktop/resources/icon.icns` | іконка (робиться з `icon.png` через `./tools/make-icns.sh`) |
| `tools/make-icon.js` | малює `icon.png` — той самий знак-хвиля, що в застосунку |

### Чому `app://`, а не `file://`

Chromium забороняє IndexedDB сторінкам, відкритим як `file://`. А саме там
лежать книги (`flow_books`) і документи агенції (`flow_docs`) — читалка й
сховище просто не працювали б. Тому вікно відкриває `app://frequency/index.html`:
для браузера це нормальний сайт зі сталим походженням, тож усе сховище доступне,
а `localStorage` переживає оновлення застосунку.

### Вхід через Google на компʼютері

У застосунку немає адресного рядка, тому Google не має куди повертати людину.
Рішення стандартне для настільних програм: вхід відкривається у **справжньому
браузері** (Google свою сторінку входу у вікні застосунку показувати забороняє),
а назад повертає через власне посилання `frequency://auth`, яке macOS віддає
застосунку.

**Щоб це запрацювало, треба один раз додати адресу в Supabase:**

> Supabase → проєкт → Authentication → URL Configuration → **Redirect URLs**
> → додати `frequency://auth`

Без цього кнопка «Google» відкриє браузер, але назад у застосунок не поверне.
Локально програма при цьому працює повністю — просто без синхронізації.

### Підпис застосунку

Збірка **не підписана**: для цього потрібен Apple Developer ($99/рік).
Для себе це не заважає. Але якщо передати `.dmg` іншій людині — macOS у неї
скаже «застосунок пошкоджено», бо не знає, хто автор.
