# Пошук кореня бага

Адаптація скіла `systematic-debugging` з [obra/superpowers](https://github.com/obra/superpowers)
(MIT, коміт `bb92a77741`, ліцензія — `LICENSE-superpowers.txt` поруч).
Перекладено й прив'язано до наших перевірок; приклади — з історії Frequency.

## Залізне правило

**Жодної правки без знайденого кореня.** Латка на симптом — це провал, навіть якщо
симптом зник: корінь лишився і вилізе в іншому місці. Так було з «папки губляться»:
кілька латок, поки не знайшли справжнє — «порожньо» не відрізнялось від
«сховище не відповіло» (тепер `saveFolders({auto:true})`).

Правило діє **особливо** коли: поспіх; «та тут одна дрібниця»; вже була спроба,
і вона не допомогла; не до кінця розумієш, що відбувається.

## Чотири фази — по черзі, без перескоків

### 1. Корінь

1. **Прочитати помилку повністю** — текст, файл, рядок. Вивід `npm run check` /
   `npm run smoke` / консоль браузера — до кінця, а не перший рядок.
2. **Відтворити стабільно.** Точні кроки, щоразу однаково. На 375×812 у прев'ю
   `dist/` (правило 3 CLAUDE.md). Дата/час → `TZ=Europe/Kiev` і граничний час.
   Не відтворюється → збирати дані, а не вгадувати.
3. **Що змінилось.** `git log -p` по файлу, останні коміти, чужі незакомічені правки
   (блок «Що в роботі» у пульті), нова міграція, інша гілка/робоча копія.
4. **Межі системи.** У Frequency дані йдуть шаром за шаром:
   `тап → функція екрана → store/saveX → localStorage → синк → Supabase → інший пристрій`.
   Перш ніж правити — подивись, **що входить і що виходить на кожній межі**
   (тимчасовий `console.log` з префіксом `DEBUG`), один прогін — і видно, на якому
   шарі ламається. Потім прибрати всі `DEBUG`.
5. **Трасувати назад до джерела** — див. `trasuvannia.md`: де з'явилось погане
   значення, хто його передав, і так угору, доки не знайдеш, звідки воно взялось.

### 2. Різниця з робочим

- Знайди схоже, що **працює** (інший екран, інша папка, той самий код на іншій гілці).
- Перелічи **всі** відмінності, навіть «це не може впливати».
- Якщо береш готовий зразок (інший файл, бібліотеку) — прочитай його повністю.

### 3. Одна гіпотеза

- Сформулюй письмово: «**Я думаю, корінь — X, бо Y**». Конкретно, не «щось із синком».
- Перевір **найменшою** зміною, одна змінна за раз.
- Не підтвердилась → **нова** гіпотеза. Не нашаровувати правки одна на одну.
- Не знаєш → так і сказати Ярославу: «я не розумію X», а не вдавати.

### 4. Правка

1. **Спершу — відтворення, що падає:** сценарій у прев'ю, автотест
   (`npm run test:migrations` для міграцій) або разовий скрипт. Має бути ДО правки.
2. **Задум правки → «так»** (правило 1 CLAUDE.md). Одна правка — у корінь.
   Без «заодно поправив поруч».
3. **Докази:** `npm run map && npm run check` («Все гаразд.»), `npm run smoke`,
   той самий сценарій — симптому нема. Видима зміна → `/frequency-verify`.
   Чіпає дані → рецензент `data-safety-reviewer`.
4. **Не допомогло?** Стоп. Скільки правок уже було?
   - менше 3 — назад у фазу 1 з новими даними;
   - **3 і більше — стоп.** Це вже не гіпотеза, а архітектура: кожна правка
     відкриває нову проблему в іншому місці. Не робити четверту латку —
     описати Ярославу, що бачиш, і обговорити, чи сам підхід правильний.

## Червоні прапорці — стоп, назад у фазу 1

- «Швидко полатаю, потім розберусь»
- «Спробую змінити X — раптом допоможе»
- «Зміню кілька речей і запущу check»
- «Мабуть, це X» — без перевірки
- Список правок до того, як простежив шлях даних
- «Ще одна спроба» — коли вже було 2+

**Сигнали від Ярослава, що йдемо не туди:** «а воно взагалі так робить?» (не
перевірив), «покажи», «не вгадуй», «ми застрягли?» — стоп, фаза 1.

## Коли кореня «нема»

Буває справді зовнішнє: мережа, iOS вбила вкладку, хмара не відповіла. Тоді:
описати, що перевірено; зробити чесну обробку (повтор, «хмара не відповіла»
замість «порожньо»); лишити слід для наступного разу. Але найчастіше «кореня
нема» = розслідування не дійшло до кінця.

## Після кореня — захист у глибину

Знайшов корінь і виправив — подумай, на яких ще шарах таке значення можна
перехопити, щоб баг став **неможливим**, а не лише виправленим. Див. другу
частину `trasuvannia.md`.
