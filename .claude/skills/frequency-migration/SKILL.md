# Міграція даних

Урок: «порожньо» колись не відрізнялось від «не відповіло», і заводська
заглушка затерла папки в хмарі на всіх пристроях. Тому — лише так.

## Кроки

1. **Задум із таблицею сценаріїв** (правило 1) для кожного ключа:
   пишеться цілком? · null з хмари · гість → вхід · офлайн-старт ·
   2 пристрої за 2 хв · у бекапі? · переживе «Скинути»?
   Плюс «як доведу». **Чекай «так».**
2. **Прапорець** `<назва>_v1` — ставиться лише **після** довіреного читання.
3. **Запуск лише після завантаження:** `foldersLoaded` для папок,
   `window.sbDataTrusted()` для хмари (`02-storage.js`).
4. **Папки — лише `saveFolders({auto:true})`** (`04-folders-nav.js`).
   Звичайний `saveFolders()` у міграції — заборонено. Для інших ключів —
   такий самий запобіжник.
5. **Ідемпотентно**, зберігати лише якщо дані змінились.
6. **Копіювати, а не видаляти** — старий ключ живе ще ≥2 публікації.
7. **Новий ключ** — у `FLOW_KEYS` (`01-base.js`), лише через `window.storage`.
   Фото й аудіо — `photoPut`, не base64 у ключі.
8. **Страховка:** перед дотиком до справжніх даних — `./tools/snapshot.sh`
   (рятує лише Mac). Перед публікацією — Ярослав робить Ще → Бекап даних
   на телефоні. `npm run dev` / `npm start` працюють зі справжніми даними —
   тести робити в прев'ю.
9. **Тест збереження** у прев'ю з тестовим профілем:
   щасливий шлях · хмара мовчить (Offline / `null`) → міграція не пише ·
   повторний запуск нічого не змінює (`JSON.stringify` до/після).
10. `npm run map && npm run check` → «Все гаразд.»
11. **Коміт** лише своїх файлів з рядком «Міграція: що → куди, як відкотити».
