# Баг з телефона

> Коли Ярослав каже «подивись баги», кидає скрін або описує, що зламалось
> на iPhone. Скіл `/frequency-phone-bug` робить те саме коротше.

## Шаблон опису бага (заповнює Ярослав)

```text
Екран: <Огляд / Папка / Чати / Планер / …>
Що роблю: <кроки>
Що бачу: <…>
Що чекав: <…>
Скрін у баги-з-телефона: так / ні
Як часто: завжди / іноді / один раз
Після оновлення сайту: так / ні / не знаю
```

---

Працюй за процесом «баг з телефона» Frequency:

1. **Зібрати скріни:** `npm run bugs` (або `./tools/bugs.sh`). Прочитай
   кожен знімок.
2. **Переказати симптом одним реченням** і спитати: «Правильно зрозумів?»
   Опис часто надиктовано голосом — не вгадуй.
3. **Знайти екран:** `grep` по `CODEMAP.md` і `grep -rn '<текст зі скріна>' src/`.
4. **Відтворити до правки** у прев'ю `dist/` на 375×812 (порт 4173) з тестовими
   даними. Показати знімок чи вивід консолі, де симптом видно.
   - Дата «не того дня» → `TZ=Europe/Kiev node -e …` з граничним часом.
   - Перекриття → `document.elementFromPoint` у центрі й по краях кнопки.
   - Не відтворюється → сказати чесно і спитати ще деталей, а не «лагодити наосліп».
5. **Задум правки** (правило 1) → чекати «так».
6. **Правка** в `src/`, `npm run map`, `npm run check` («Все гаразд.»).
7. **Показати, що симптому більше нема** — той самий сценарій, що в кроці 4.
   Далі `/frequency-verify`.
8. **Коміт** лише своїх файлів. На телефоні фікс видно лише після публікації
   і 1–2 перезапусків PWA (кеш service worker) — сказати про це прямо.

**Ніколи** не копіюй скріни в репо чи `dist/`: на них особисті дані, а репо публічне.
