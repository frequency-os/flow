# Міграція даних

> Для будь-якого коду, що **при старті сам змінює збережені дані**: разова
> міграція (`*Once`, `migrate*`), новий ключ сховища, заводський дефолт,
> зміна формату. Скіл `/frequency-migration` — коротка версія.

Чому окремий процес: «порожньо» вже раз не відрізнялось від «не відповіло»,
і автоматичний запис заводської заглушки затер папки в хмарі на всіх пристроях.

## 1. Задум із таблицею сценаріїв (чекай «так»)

Заповни для кожного ключа, який пишеш:

| ключ | пишеться цілком? | null з хмари (не відповіла) | гість → вхід | офлайн-старт зі старою копією | 2 пристрої за 2 хв | потрапляє в бекап? | переживе «Скинути»? |
|---|---|---|---|---|---|---|---|

Плюс рядок **«Як доведу, що втрати нема»** — конкретний сценарій у прев'ю.

## 2. Правила коду

- **Прапорець «виконано»**: ключ `<назва>_v1` у сховищі (як `theme_flat_default_v1`). Ставиться лише
  **після** довіреного читання даних, не раніше.
- **Запускати лише після підтвердженого завантаження:** `foldersLoaded` для
  папок, `window.sbDataTrusted()` для хмари (`02-storage.js`).
- **Папки — лише `saveFolders({auto:true})`** (`04-folders-nav.js`). Він сам
  відмовиться писати, якщо дані сесії не прочитано або в пам'яті заводська
  заглушка при повному сховищі. Звичайний `saveFolders()` у міграції — заборонено.
- Інші ключі — власний запобіжник за зразком `saveFolders`: не писати, доки
  ключ цієї сесії не прочитано і `window.sbDataTrusted()` не повернув `true`.
- **Ідемпотентність:** повторний запуск нічого не міняє. Зберігати лише якщо
  дані справді змінились.
- **Копіювати, а не видаляти.** Старий ключ лишається щонайменше на 2 публікації.
- **Новий ключ** — у `FLOW_KEYS` (`01-base.js`) і лише через `window.storage`,
  інакше його нема в бекапі й синку.
- Нічого бінарного в ключах: фото й аудіо — `photoPut` (PhotoDB), у даних лише посилання.

## 3. Страховка даних

- **Перед будь-яким дотиком до справжніх даних** — `./tools/snapshot.sh`.
  Він рятує лише сховище **Mac**, не хмару й не телефон.
- Перед публікацією з міграцією — Ярослав робить **Ще → Бекап даних** на телефоні.
- Відтворювати сценарії — у прев'ю (порт 4173) з тестовим профілем, не в `npm run dev`
  (той працює зі справжніми даними).

## 4. Тест збереження (доказ)

У прев'ю на 375×812:

1. **Щасливий шлях:** стара форма даних → перезавантаження → дані в новій
   формі, прапорець стоїть, у старому ключі все на місці.
2. **Хмара мовчить:** вимкни мережу (DevTools → Offline) або підміни відповідь
   на `null` → перезавантаження → міграція **не** пише, у консолі
   «saveFolders пропущено…», дані не змінились.
3. **Повторний запуск:** ще одне перезавантаження → нічого не змінилось
   (порівняй `JSON.stringify` до і після).
4. `npm run map && npm run check` → «Все гаразд.»
