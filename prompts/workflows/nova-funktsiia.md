Працюй за процесом «нова функція» Frequency:

## 1. Розвідка (без правок)

- `git status` і `git worktree list` — чи нема чужих незакомічених правок.
  Якщо дерево «чуже» — працюй у своєму worktree.
- Знайди в `CODEMAP.md` (grep, не читати цілком) системи, яких це торкається.
  Прочитай лише потрібні рядки.
- Визнач тип задачі за правилом 1 CLAUDE.md. Новий файл у `src/scripts/core/`
  чи зміна структури = **нова система**.

## 2. Задум (чекай «так»)

- Питання — **по одному**: мета, обмеження, за чим видно, що вийшло.
- Для нової системи — **2–3 варіанти з чесними мінусами** кожного.
- Опис по пунктах: які файли, які нові функції (з префіксом модуля —
  усі файли core склеюються в один скрипт), які ключі сховища, як доведеш.
- Якщо торкаєшся **даних** — додай таблицю сценаріїв з
  [`mihratsiia-danykh.md`](mihratsiia-danykh.md).
- Якщо торкаєшся **агента** — дивись [`novyi-instrument-ahenta.md`](novyi-instrument-ahenta.md).
- Якщо з'являється **екран** — [`novyi-ekran.md`](novyi-ekran.md).
- Якщо є **видалення чи нова шторка** — у задумі: підтвердження або undo,
  тап-зона ≥44×44, спільні хелпери `confirmSheet`/`actionSheet`.

## 3. Код

- Правлять лише `src/`. `dist/` не чіпати. Номери файлів core не міняти.
- Спільні хелпери — з `01-base.js` (`ymdLocal`, екранування тощо), власних копій не писати.
- Дані з мережі, хмари, AI чи файлів — у HTML лише через екранування.
- Коментарі українською, пояснюють «чому».
