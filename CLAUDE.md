# Правила роботи над Frequency

Цей файл читає Claude на початку кожної сесії. Тут лише те, чого не видно з коду.

---

## Два залізні правила

### 1. Спершу задум — потім код

**Не писати код, доки я не сказав «так» на твій задум.**

Обсяг обговорення залежить від розміру задачі, але сам крок не пропускається ніколи:

| Тип задачі | Що робиш перед кодом |
|---|---|
| **Розвідка** (чи це взагалі можливо, тимчасовий код на викид) | 2–3 речення: що перевіряєш і як. Дочекайся кивка |
| **Точкова правка** (зміна в наявній системі з `CODEMAP.md`) | Уточнювальні питання → короткий опис у чаті → чекай згоди |
| **Нова система** (новий файл у `src/scripts/core/`, зміна структури) | Питання → 2–3 варіанти з чесними мінусами → опис по пунктах → чекай згоди |

Питання став **по одному**, не списком. Питай про мету, обмеження і за чим
буде видно, що вийшло. Де можеш — давай варіанти на вибір, а не відкрите поле.

«Просто» означає короткий задум, а не відсутність задуму.

### 2. Не казати «готово» без свіжого доказу

**Жодних заяв про успіх без щойно запущеної перевірки.**

Порядок дій перед будь-яким «працює / готово / полагодив»:

1. Назви команду, яка це доводить
2. Запусти її **зараз**, повністю — не згадуй результат минулого разу
3. Прочитай увесь вивід, порахуй помилки
4. Якщо вивід не збігається із заявою — кажи, що насправді сталося
5. Тільки тоді заявляй — і покажи вивід

Наша команда-доказ:

```bash
npm run check
```

Вона перевіряє синтаксис усіх JS справжнім движком, збирає програму, звіряє
автономність (чи не тягне сайт щось із мережі при старті) і показує різницю
з еталоном `original/index11.html`.

**Стоп-сигнали — так писати не можна:**

- «має працювати», «схоже, вийшло», «майже певен» — це не перевірка
- «Готово!» до того, як запущено `npm run check`
- Виправив баг, але не відтворив початковий симптом і не показав, що він зник
- Комітити чи викладати без доказу

Виправлений баг = симптом відтворено і показано, що його більше немає.
Не «код виглядає правильно».

## Що важливо знати про проєкт

- **`dist/index.html` НЕ редагують.** Правлять `src/` → збірка (`npm run build`).
  Пряма правка `dist/` зникне при наступній збірці.
- **Порядок файлів у `src/scripts/core/` — це порядок виконання.** Номери
  (`01-`, `02-`…) міняти не можна.
- **Перед читанням коду — `CODEMAP.md`.** Файл на 34 тисячі рядків не треба
  тягнути в контекст цілком; карта каже, у якому діапазоні шукати.
- **Версії бібліотек у `src/vendor/` зафіксовані навмисно.** Не оновлювати
  без мого прямого рішення.
- **Код рятує git, дані рятує `./tools/snapshot.sh`.** Це різні страховки,
  одна іншу не замінює. Перед ризикованою правкою даних — знімок.
- Мова коментарів, комітів і спілкування — українська.
